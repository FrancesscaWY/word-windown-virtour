# 文字对话本地规则：诊断期间暂停

为排查文字对话“秒回但后端没有请求”，`src/services/guide.js` 的 `createGuideResolver` 默认使用 `localRules: false`。所有通过文字输入框提交的非空有效内容都请求 `/api/guide`，不再命中本地模板答复或页面指令。离线、未配置或网络故障只显示错误，不回退本地回答。

## 原有规则覆盖

规则实现仍保留在 `src/guide/intent.js`，现在不会在默认文字分流中执行：

- 停止、暂停、继续讲解、确认、拒绝以及否定表达。
- 返回地图、打开景点、介绍或重听景点。
- 建筑故事、详情、多个景点选择、指代不清时的澄清。
- 拍照、建筑、亲子与通用景点推荐。
- 卫生间、出入口、服务、餐饮和停车设施查询。
- 距离、步行时间、人流、排队的本地固定说明。
- 保存、下载请求的“不支持”固定回复。

路线规划、天气和票务等原先已有部分请求走后端，现在也保持同一后端链路。

## 保留的边界

- 不改 UI 布局。地图标记、设施按钮、返回地图按钮、停止播放按钮、角色重听等直接操作仍在本地执行。
- 语音原本已经调用后端模型。本次不改其音频链路；识别字幕用于页面联动和语音紧急停止的本地处理仍保留，通话打断不等待文字模型。
- 原规则与控制器保留，便于恢复。需要恢复旧的文字分流时，在 `src/main.js` 中显式配置 `createGuideResolver({ localRules: true })`；默认不启用，没有新增页面开关。
- 开发服务直接读取源码，无需重启后端；已有页面需要刷新才会加载新模块。此前 README 中“文字地图指令本地执行”的介绍不适用于这个临时诊断状态。

## 验证

`tests/backend.test.mjs` 覆盖 25 组原规则用语，逐项确认现在都调用后端，同时验证错误不回退、上下文与取消信号传递、按钮本地操作和显式恢复选项。
