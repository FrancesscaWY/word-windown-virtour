# 沿手绘底图描绘的路网

## 当前实现

用户反馈 OSM 配准线与插画道路仍完全不符，明确要求自行绘制路网覆盖底图。现在直接以 `public/assets/map.jpg`（1339 × 1174）上的浅色道路为视觉依据，逐段标注路径、转弯与交叉口。旧 OSM 叠层不再用于页面路网或规划路线。

目前包含 107 段路径、88 个命名端点／路口和 3806 个采样点，覆盖湖岸、瀑布、金字塔、圆形广场、欧洲建筑花园、亚洲区和南侧水岸。仅描绘图中可辨识的路段；图上的红色虚线没有被直接当作整套步行路网。曲线为人工控制点平滑采样，约每两图像像素一点。

道路使用图像百分比坐标，缩放和拖动时与底图保持同一变换。右侧「路网」按钮继续显示/隐藏图层并记忆状态。景点和设施原地理坐标保持不变，其标记继续采用已有视觉配准。

## 路线与来源

- 现有 `plan_route` 工具在 `server/ai/tools.ts` 注册并直接执行 `server/ai/routes.ts` 的 `planRoute`，后者加载 `artworkNetwork()`。当前显示的路网与工具寻路都读取 `src/data/artwork-roads.js`，共用同一内容指纹。
- LLM 选择景点及顺序，后端 `server/ai/artwork-network.ts` 在手绘图的共享节点上寻路，前端接收成功结果后沿同一几何播放动画。
- 路线类型为 `geometry.kind: artwork-traced`，坐标为 `coordinateSpace: artwork-percent`，前端直接使用，不能再次经过地理配准。
- 每段路线保留 `roadIds`、`nodeIds`、`stopIndices`、`legs` 与数据指纹。前端校验每条边确实属于手绘路网，防止恢复旧 OSM 线或直线代替。
- 标题、站点序号、逐段动画、聚焦、清除、减少动态效果及失败保留上一条路线继续生效。文字、一次性语音和全双工通话共用后端工具。
- 图像像素只用来比较示意路径长短，不换算成真实米数。`distanceMeters` 返回 `null`；工具和页面明确称为「手绘路网／游览路线示意」，不冒充实测道路、核实入口、实时通行或无障碍导航。
- 景点资料的 OSM 来源与路网来源分开保留；手绘道路的来源是本地底图，而不是 OSM way。

## 修改与再生成

1. 修改 `scripts/artwork-road-controls.mjs`：`junctions` 是共享路口像素坐标，`roads` 是两个路口及沿途的人工描绘点；主路和支路分别标记 primary／secondary。
2. 明确共用节点才能形成连接。线条视觉交叉不会自动加入路口；修改交叉口时需相应拆分路径。
3. `stopAnchors` 可显式指定景点在图上对应的道路位置；未指定时按已有显示锚点匹配附近的手绘道路点。这些点均不是核实入口。
4. 运行 `node scripts/trace-artwork-roads.mjs`，生成 `src/data/artwork-roads.js`。生成数据包括底图 SHA-256 和自身内容指纹。
5. 检查放大叠图与浏览器截图，重点避免道路穿过建筑轮廓、水面和花坛。更换底图时需要重新描绘，不能只更新文件哈希。
6. 后端缓存当前路网，修改后重启统一 proxy 入口，再刷新页面。

`tests/artwork-roads.test.mjs` 验证来源指纹、路网连接、44 个已定位景点的图上锚点、断路处理以及不生成真实距离。`tests/routes.test.mjs` 验证几何与图层一致、拒绝旧坐标类型及篡改路段。浏览器回归使用 `scripts/verify-road-network.mjs` 和 `scripts/verify-routes.mjs`。

临时描绘参考和叠图位于 `agent-tmp/artwork-roads/`，页面截图位于 `agent-tmp/road-network/`、`agent-tmp/routes/`。
