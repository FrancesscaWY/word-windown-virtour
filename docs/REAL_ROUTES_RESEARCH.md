## 结论

已从 OpenStreetMap 官方 API 取得园区道路几何，并验证了斗兽场、凯旋门、铁塔附近道路节点间的连通路径。数据足以支持后端沿已收录道路计算路线，但不等同于官方实时导航；景点入口连接、道路现状仍需核对。

当前生产实现 `server/ai/routes.ts` 已返回真实道路节点序列、锚点、分段与来源；`src/components/planned-route.js` 沿该几何绘制。LLM 选择顺序，后端负责几何与校验。数据不可用或道路不连通时返回失败，不绘制替代直线。

## 可用来源与覆盖

- 数据 API：<https://api.openstreetmap.org/api/0.6/map.json?bbox=113.9624,22.533,113.9736,22.5421>
- 园界：<https://www.openstreetmap.org/way/236402460>，本次取得版本 45。
- 许可与署名：© OpenStreetMap contributors，ODbL 1.0，<https://www.openstreetmap.org/copyright>。
- 本次响应含 9,188 个 OSM 对象。以至少一个节点位于园界内筛选，得到 67 个带 `highway` 的 way：30 个 footway、27 个 pedestrian、5 个 steps、4 个 service、1 个 path。way 是数据对象，不等于 67 条独立命名道路。
- 试验排除 `area=yes` 及明确 `foot/access=no/private` 的对象后剩 64 个 way；只连接两端均在园内的相邻原始节点，不凭空连接相近但不共享节点的道路。
- 试验图含两个连通分量，节点数分别为 486 和 8。44 个有坐标景点各自最近的道路节点均落在主分量，距景点目录中心约 0—99 米。这仅说明路网覆盖接近景点，不表示这些节点就是可用入口。

完整 API 数据已有项目快照 `public/assets/world-window-osm-source.json`。本次重新下载的响应保存在 `agent-tmp/real-routes/osm-live.json`，SHA-256 为 `50232fcd538a19f51ce87d9700af3f2ae09843b767302016353ea85fdc2754e0`。

## 沿路连通验证

试验顺序为斗兽场 → 凯旋门 → 铁塔；取各景点附近的已收录道路节点，以相邻节点几何长度作为权重运行 Dijkstra。

- 斗兽场附近节点 `5778992639` → 凯旋门附近节点 `10705991214`：17 个节点，约 110 米。
  - 使用 way：`610188518`、`610188520`、`1150884216`、`1150884217`、`1150884219`。
- 凯旋门附近节点 `10705991214` → 铁塔附近节点 `2699879607`：9 个节点，约 105 米。
  - 使用 way：`1150884220`、`1150884222`、`1150884216`、`264196046`。

上述长度仅为试验道路节点间的几何长度，不含景点入口连接，不应直接作为游客行走距离。斗兽场和铁塔的目录中心分别距离选取的路网节点约 10 米和 25 米。

## 接入时的地图约束

`src/data/external-assets.js` 展示 `public/assets/map.jpg` 手绘图，而景点源位置使用 OSM 地理坐标。最初截图中建筑插画与对应标记有明显偏移，真实道路直接叠加也会错位。

用户选择保留手绘图；现已使用 68 个视觉控制点进行分片仿射配准，路网、路线与标记共用显示坐标。局部仍是近似视觉贴合，不能仅通过控制点命中认为已有地理导航精度。

后端保持负责工具执行与路网寻路，LLM 决定游览站点顺序；前端只渲染成功结果，沿道路逐段播放绘制动画，沿用站点序号及地图工具栏，不添加路线弹窗。
