# 文字对话诊断日志

只改后端，不改前端界面、请求参数或返回 JSON。重启服务后，每次 `POST /api/guide` 自动记录一份独立日志；没有增加任何公开日志 API 或管理网页。

## 查看

在项目目录的服务器终端执行：

```bash
npm run chats:inspect
```

默认查看最新一轮，包括问题、回答、携带的历史和页面上下文、模型轮次耗时与 token 用量、工具参数与状态，以及错误详情。

```bash
# 最近 20 轮的索引（默认按时间倒序，含失败和未完成的请求）
npm run chats:inspect -- --list --limit 20

# 指定轮次
npm run chats:inspect -- --id <chatId>

# 展开时间线、实际系统提示和历史、模型回复、完整工具结果
npm run chats:inspect -- --id <chatId> --events
```

`--id` 从列表取得；不传 `--id` 时可用 `--events` 展开最新一轮。输出为 JSON，可重定向到项目的 `agent-tmp/` 下做离线分析。

## 文件与事件

默认目录为 `logs/chats/YYYY-MM-DD/<chatId>/`，日期使用服务端 UTC。`.env` 中的 `CHAT_LOG_DIR` 可覆盖根目录（推荐绝对路径）；查看命令读取同一设置。每轮目录含：

- `events.jsonl`：逐条追加的事件，含唯一 `chatId`、服务端 `requestId`、顺序号、UTC 时间和相对耗时。包括请求、实际送入模型的规范化历史和页面上下文、每次模型请求/响应/异常、工具开始/结束、最终回答、取消与请求结束。
- `summary.json`：轮次结束后原子发布的摘要，含结果状态、HTTP 状态码、总耗时、模型、问题/回答、用量、工具概览和日志完整性。不存在表示仍在执行，或进程非正常退出，**不等同于回答成功**。

结果状态：`success`、`error`、`timeout`、`cancelled`、`rejected`。客户端中断记为取消，后台可用 499 表示已断开的请求；不会改变原有前端错误提示或 HTTP 错误协议。正常请求收尾和服务正常关闭会冲刷日志；强制终止/掉电可能留下未完成的 JSONL 行，查看器会报告 `unreadableLines`。

## 范围与安全

- 当前只为后端文字 AI 请求记日志。本地直接处理的“返回地图”“找卫生间”等操作不会请求后端，**无法在不改前端的情况下记录**。实时通话已有独立 `logs/calls/`，使用 `npm run calls:inspect`，不受此改动影响。
- 每份日志对应一轮 HTTP 请求，不伪造用户或会话 ID。连续对话通过请求中已有的最近至多 10 条历史定位；前端刷新前且未发送到后端的内容不保证存在。
- 不保存请求头、API 凭据、供应商隐藏推理或原始环境变量。已配置的文字/语音密钥、Bearer 内容及常见敏感字段会脱敏；模型异常详情仅落到服务端，仍不返回给游客。
- 日志包含完整问答和工具内容，不能视为匿名数据。新建目录权限 0700、文件 0600；`logs/` 已被 Git 忽略，也不在页面静态资源目录中。自定义目录**不能放在 `public/`、`src/` 或 `dist/` 等被网站公开的路径下**，已有目录权限也需自行核查。
- 单条事件约 2 MiB、每轮约 16 MiB 的内容限制，省略时写明 `log.omitted`，摘要 `logging.complete=false`。待写缓冲区限制 4 MiB，磁盘错误/积压不会阻塞问答；服务端会输出 `Chat journal ... failed`，可写摘要会标记不完整。
- 按日期分目录，但目前没有自动过期删除。请按诊断所需保留期限定期清理或归档，留意磁盘容量。关闭日志读取命令不会停止后端记录。
